# R3-4: Multiplayer agent sessions for engineering teams, with manager visibility (YC RFS #4)

Evaluator stance: YC partner plus former VP Eng, scoring against `RUBRIC.md`. I set out to disprove the idea, and the benchmark is ContextOps at 58. Date: 2026-10-13.

## 1. The idea and its best honest framing

**As pitched.** Teams share live coding-agent sessions and plans. EMs and tech leads see what each person and their agents are working on, and can step in. The idea answers YC's Fall 2026 RFS #4, "Multiplayer AI" (Epstein): "Anyone on a team should be able to drop into the same live agent session to watch it work, redirect it, and hand it off... Shared agents for engineers coding together in real time" (`data/yc_rfs.txt`). It also fits the founder's origin story, a manager who didn't know what he was working on.

**Sharpest version I could construct.** A *vendor-neutral team agent ledger*. Every Claude Code, Codex and Cursor session is captured through hooks or OTel and linked to its branch, PR and Linear issue. The ledger is searchable and resumable by teammates. Managers get a *work-stream* view ("what is in flight on project X, what is blocked waiting for a human"). They do not get a per-person view. The IC controls what gets published.

This version dodges the worst surveillance problems, and neutrality is the only defensible lane. I scored this version. It still scores badly.

## 2. Competition: the category was filled before we arrived

### First-party tools already ship the core feature

- **Claude Code.** Cloud sessions on Team and Enterprise plans have a **"Team" visibility** toggle that "makes the session visible to other members of your claude.ai organization". Sessions started from Claude in Slack are "automatically shared with Team visibility". Teammates can leave inline diff comments and steer from any device. The one gap is that shared views "don't update in real time" ([Claude Code on the web docs](https://code.claude.com/docs/en/claude-code-on-the-web)).
  - Admins also get an analytics dashboard with per-user sessions, PRs with Claude Code, a **leaderboard**, and CSV export of all users ([analytics docs](https://code.claude.com/docs/en/analytics)).
  - Projects coordinate parallel cloud sessions. They are Pro/Max only today, and Team/Enterprise is the obvious next step ([Projects docs](https://code.claude.com/docs/en/claude-projects)).
  - Mosaic's own YC blurb claims its multiplayer prototype "inspired frontier labs like Anthropic". Whether or not that is true, the lab has shipped the primitive.
- **Cursor.** Cloud agents are "visible to members of the Cursor team they were started under". Admins can enable **team follow-ups**, which let teammates send instructions to someone else's agent, and agents can be started from Slack and Linear with @cursor ([Cursor cloud agent docs](https://cursor.com/docs/cloud-agent)). That is RFS #4's "watch, redirect, hand off", already shipped.
- **GitHub Copilot coding agent.** Its documentation states: "Shared sessions and pull requests let teammates with repository access follow the work and review changes." Session logs are attached to the PR, and remote control lets you steer CLI sessions from github.com ([GitHub docs](https://docs.github.com/en/copilot/concepts/agents/coding-agent/about-coding-agent)).
- **Linear.** Agents get user pages that list their activity. You can filter any view by "Delegate", and Insights can be segmented by agent ([Linear docs](https://linear.app/docs/agents-in-linear)). For a manager, *Linear already is* the work-stream view of agent work.
- **Devin.** Slack and Teams threads are a first-class entry point, so teammates see the work in the channel ([Devin docs](https://docs.devin.ai/get-started/devin-intro)).

### Well-funded independents are already present

- **Delta**, from the Zed team, is in beta. It offers real-time multiplayer agent threads, line-anchored comments, sharing scoped to the org, and handoff to a cloud runner ([delta.dev](https://delta.dev/)). This is exactly the RFS, built by a team with a collaborative-editor pedigree and Zed's distribution.
- **Conductor** launched "multiplayer cloud workspaces" ([runtimewire](https://runtimewire.com/article/conductor-launches-multiplayer-cloud-workspaces-coding-agents)).

### YC entrants

- **Agent Relay** (F26). Teams "can see what every agent is doing... and step in when human judgment is needed". It is open source and self-hostable, with a free cloud tier. It names no customers and lists only investor logos ([agentrelay.com](https://agentrelay.com)). This is nearly word-for-word our pitch.
- **Mosaic** (S26). "Everyone's AI coding sessions, in one place", installed through a Homebrew CLI. The site gives no pricing, customers or funding ([mosaic.inc](https://mosaic.inc)). It pivoted *away* from live real-time co-editing to shared memory, which is a quiet signal that live multiplayer did not retain users.
- **Dock** (S26) targets business-function agents, not software engineering. **Terse** (F26) is "durable state for AI agents", infrastructure underneath multiplayer. Neither is a direct competitor, but both show YC spreading the RFS thin.

### The long tail of Show HNs (Algolia, `rsearch.py`)

- Grov, "Multiplayer for AI coding agents", 24 points.
- Amika, 7. AQ, 4. Collaborate.dev, 3. HumanLayer, 1.
- Cyrus, "team multiplayer coding agents... in Linear and Slack", 6.
- Agentlore, a "searchable team log for AI coding agent sessions" linked to PRs, 2. This is our sharpened version, already built on Wes McKinney's agentsview.
- Egregore, 5. CoChat, "let your team review what your coding agent is building", 5. SageOx, 4. Draft, 1.

At least **15 entrants** in about 9 months, and almost all of them got under 25 points.

## 3. Demand: mostly supply-side noise

**Strongest signals.**
- YC wrote an RFS for this.
- Skillsync (YC W26), portable AI sessions, got a Launch HN with 68 points and 62 comments.
- "Real-time dashboard for Claude Code agent teams" got 77 points, and Mission Control got 45 points. But both of those dashboards serve a *solo* developer managing *their own* agent swarm, not a team or a manager.

**The disproving evidence.**
1. The volume of builders, against the near-absence of launch traction, means the supply is chasing an RFS rather than buyer pull.
2. No entrant shows pricing or a named customer. That includes Agent Relay, Mosaic, Delta and Grov.
3. Mosaic's pivot from live sessions to memory suggests that *real-time* co-presence in agent sessions is a demo, not a habit. Engineers rarely pair-program today. Agents make work *more* asynchronous, not less.
4. A Grov commenter had "built and abandoned a similar tool" and noted that "amp tried a variant and pivoted" ([HN 46711958](https://news.ycombinator.com/item?id=46711958)).
5. The manager half has the weakest evidence of all. Round 1 found real pain in *managers not knowing or remembering IC work* (Julia Evans on brag docs; Gallup spans rising to an average of 12.1). But the fix people adopt is a narrative (brag docs, 1:1 briefs), not watching agent transcripts. No EM wants to read 40 session logs a day.
6. Round 1's Manager Memory (idea03) scored **45** because Claude plus MCP connectors already produces the brief. This idea inherits that problem and adds a crowded multiplayer layer.

## 4. Surveillance risk: structural, not cosmetic

"Managers see what each person and their agents are working on" turns full prompt transcripts into evaluation data. Transcripts are far more revealing than commits: they show confusion, dead ends, and time-of-day.

The evidence from round 1:
- Harness found that 54% of developers fear evaluations based on AI data, and 55% want improvement data separated from performance data ([IT Brew](https://www.itbrew.com/stories/developers-fear-performance-evaluations-based-on-ai-data-survey)).
- Cornell found that AI monitoring drew more than 4x the complaints of human monitoring and led to worse performance, *unless* it was framed developmentally ([Cornell](https://www.news.cornell.edu/stories/2024/07/more-complaints-worse-performance-when-ai-monitors-work)).
- Under the EU AI Act, systems that monitor or evaluate worker performance fall under Annex III high-risk, and German works councils hold §87 BetrVG co-determination rights ([Faegre Drinker](https://www.faegredrinker.com/en/insights/publications/2026/6/draft-commission-guidelines-on-high-risk-ai-implications-for-the-workplace)).

Anthropic's own per-user leaderboard is already visible to admins. A startup that goes *further* (transcripts plus a manager view) takes on more legal and trust risk than the platform does, while offering less.

The consent-first framing (IC publishes, team-level view) reduces the risk but also removes the manager value. It leaves a shared-session tool, which is exactly what the vendors gave away.

## 5. Scores

**A. Proven demand / market: 8/20**
- For: an explicit YC RFS, and a hot "agents for teams" trend.
- Against: zero evidence of money. No entrant has pricing or customers. Launches mostly get under 10 points. The most visible YC player pivoted away from the live-session premise. The manager-visibility half has no willingness-to-pay evidence beyond round 1's weak 1:1-tool category ($2-7 per seat, Lattice free).

**B. Sellable: 6/20**
- Every platform a team standardizes on includes team sharing at no extra cost: Claude Team visibility, Cursor team follow-ups, Copilot shared sessions, Linear's Delegate views.
- Most teams standardize on one or two agents, so the cross-vendor neutrality argument is real but small.
- The budget line is unclear. Is this a devtools seat, or EM tooling that HR will veto?
- Open-source alternatives (Agent Relay, Agentlore, Grov) cap the price.

**C. AI-durability: 4/20**
- This is the definition of "a feature GitHub, Anthropic or Cursor ships next quarter", and they shipped it *last* quarter.
- Real-time sync is the only missing piece in Claude Code. Projects for Team plans is an announced trajectory.
- The moat (session data) lives with the vendor that runs the session, especially as sessions move to vendor clouds.
- It gets worse as agents run in first-party clouds.

**D. Evidence-backed real problem: 7/15**
- Sources for the manager-visibility pain: Evans, Gallup and Blind (round 1).
- Sources for the shared-context pain among agent users: Grov and Skillsync comments.
- But the *specific* job "watch or redirect a teammate's live agent session" has no independent survey or community evidence. It rests on a VC thesis and builder enthusiasm.

**E. Specific, reachable buyer: 5/10**
- The user split is muddy. ICs adopt shared sessions; EMs want visibility; the Dir Eng or security team approves transcript capture.
- Reachable via HN, Claude Code communities and r/EngineeringManagers.
- But the buyer for the paid manager layer is unclear, and EU buyers face works-council review.

**F. Feasibility & wedge: 7/15**
- The MVP is easy: Claude Code hooks and OTel, a Codex session-file watcher, a web viewer, and PR linking. It takes weeks.
- But that ease is the problem. Fifteen others did it, and Agentlore is open source.
- Capturing full transcripts of private code triggers security review and SOC2 questions on day one.
- Real-time "drop in and redirect" across vendors needs control of the agent runtime, which the vendors own.
- No differentiated wedge survives a comparison with Delta or Agent Relay.

## 6. Verdict

RFS #4 is a VC thesis that arrived after the platforms had already shipped its core. Claude Code Team-visible sessions, Cursor team follow-ups, Copilot shared sessions and Linear agent views together cover "watch, redirect, hand off". Delta (Zed), Agent Relay (YC F26), Mosaic (YC S26) and a dozen open-source tools cover what is left.

The manager-visibility angle is where the founder's story lives. It adds surveillance and EU high-risk exposure without adding a moat, and round 1 already showed it to be a commoditized prompt (Manager Memory scored 45).

The only salvageable piece is a narrow *cross-vendor session ledger linked to PRs*, as a feature inside ContextOps (attribution and cost). It is not a standalone company. This idea scores well below the ContextOps benchmark of 58.

**Strongest demand signal:** YC's explicit RFS, plus about 15 builders in 9 months, Skillsync's 68-point Launch HN, and 77- and 45-point solo agent-dashboard Show HNs.

**Biggest risk:** Platform absorption. Anthropic, Cursor and GitHub already ship team-visible, steerable agent sessions for free, and they control the runtime where sessions live.

FINAL SCORE: 37/100

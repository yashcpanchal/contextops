# R3-2 Self-maintaining API integrations ("Dependabot for APIs", YC RFS #13): independent evaluation

Evaluator: Opus, 2026-10-13. Inputs: TOP_R3.md, RUBRIC.md, round3/yc_newest_rfs.md, round3/data/yc_rfs.txt, round2/migrations.md, round2-scoring/R2-5.md. I also ran about 10 WebFetch calls on primary vendor pages, 4 WebSearch queries, and about 15 HN Algolia queries through the helper. Items marked [background] come from prior knowledge and were not re-verified.

## The idea
A GitHub App watches the third-party APIs and SDKs a codebase calls (Stripe, Twilio, OpenAI, Salesforce, Shopify, Meta) for deprecations and breaking changes, maps each change to the affected call sites, and opens tested PRs. The proposed buyer is a VP Eng or platform lead. The RFS author (Harsha Gaddipati) frames it either as per-provider agents ("Install Stripe's update agent") or as "a neutral third-party service tracking changes across vendors". He cites one anecdote: at AWS, "over 30% of our service downtime was due to external api/package changes going unnoticed" (yc_rfs.txt, lines 166-175).

## How often do APIs actually break? (primary sources)
- **OpenAI** has published about **37 deprecation notices since 2023**, and 11 are still upcoming. Examples: the Assistants API shuts down on 2026-08-26; GPT-4 series models on 2027-01-14; Evals, Agent Builder and reusable prompts on 2026-11-30; plus repeated rounds of snapshot and chat-model sunsets ([OpenAI deprecations](https://developers.openai.com/api/docs/deprecations)). This is the highest-churn API of the group. Most notices only require swapping a model string, but some remove whole product surfaces.
- **Shopify** releases a version every quarter. Each is supported for at least 12 months. Calls to a retired version silently "fall forward" to the oldest supported one. Apps that keep using unsupported resources "can be delisted from the App Store" ([Shopify versioning](https://shopify.dev/docs/api/usage/versioning)). This is the most coercive cadence I found.
- **Meta Graph API** ships about three versions a year, and each lives about 2.3-2.4 years (for example v21.0 runs from 2024-10-02 to 2027-01-21). "Out-of-cycle changes ... usually apply to all API versions immediately" ([Graph API changelog](https://developers.facebook.com/docs/graph-api/changelog/)).
- **Stripe** pins each account and SDK to a dated version (currently `2026-09-30.endive`). Old versions keep working through compatibility layers. One HN commenter: "your decade old code will still work" ([HN 46239028](https://news.ycombinator.com/item?id=46239028)). Upgrading is therefore *optional* and deferred indefinitely, so the pain stays low. Stripe's upgrade guide is mostly about webhook endpoint juggling, sandbox testing and Workbench usage views ([Stripe upgrades](https://docs.stripe.com/upgrades)).
- [background] Salesforce retired SOAP/REST API versions 21-30 in 2025. Twilio has repeatedly announced product EOLs (Programmable Video, Authy API). X/Twitter removing v1.1 broke "hundreds of products simultaneously" in 2023 ([PageCrawl summary](https://pagecrawl.io/blog/saas-api-deprecation-sunset-notice-monitoring)).

**Read:** breakage is real and has a calendar, but it clusters in a few vendors (OpenAI, Shopify, Meta, Salesforce). The most famous API (Stripe) is specifically engineered so you never *have* to upgrade.

## Cost of integration maintenance
Hard data is thin. Postman's 2025 State of the API reports that "69% [spend] 10+ hours per week on API-related tasks". Only 26% use semantic versioning, and 55% struggle with inconsistent docs. The report has **no statistic on breaking changes or integration maintenance** ([Postman 2025](https://www.postman.com/state-of-api/2025/)). Stripe's 2018 Developer Coefficient (17.3 h/week on maintenance) is old and not API-specific (round2/migrations.md). The only directly on-topic voice: an Ask HN validating "VibeInfra" drew 5 comments. One practitioner said integration breaks "involve money ... an upstream system sent a code or format that was not agreed upon". Asked whether they would outsource integration reliability, they said **"No, because it involves money"** ([HN 46937877](https://news.ycombinator.com/item?id=46937877)). HN story searches for "API deprecation", "Stripe API version upgrade" and "Graph API deprecated" returned almost no complaint threads, and the Stripe hits were praise for its versioning.

## Competition and substitutes
1. **Supply without demand: a crowd of hobby clones appeared after the RFS.** Patch (Apache-2.0, "turns API breaks into PRs", tests-gated, TS only; **1 upvote** on Product Hunt, [PH](https://www.producthunt.com/p/patch-4/patch-6)). Also Repairo ([HN 49254765](https://news.ycombinator.com/item?id=49254765)), "YC Self-Maintaining APIs but Open-Source" / emend ([HN 49297331](https://news.ycombinator.com/item?id=49297331), 1 point, 0 comments), apipatch on PyPI, BreakShield CI, JEV OAS Sentinel, and ApiRift (a changelog-polling registry with severity scoring). None has traction. So the MVP is a weekend project, and there is no visible pull.
2. **Providers are already doing the per-provider version, and with agents.** Stripe's upgrade docs now open with "Integrate with Stripe using skills and plugins ... run `stripe agent setup`", which installs Stripe-maintained agent skills plus MCP into whatever coding agent you use ([Stripe skills](https://docs.stripe.com/skills)). Workbench already shows which API versions your integration calls. Shopify's partner dashboard [background] flags deprecated API calls per app. The RFS's "Install Stripe's update agent" is roughly what Stripe shipped.
3. **General coding agents do the edit.** Brex reports Cursor agents that open draft PRs, watch CI and deploy to dev for framework upgrades, with a 3-attempt cap ([Brex](https://www.brex.com/journal/agent-automations-for-big-migrations)). Aviator Agents markets "update all usages of a deprecated API across a monorepo" ([Aviator](https://aviator.co/blog/?p=4095)). Claude Code, Codex and the Copilot coding agent will do "upgrade us to Stripe 2026-09-30" from an issue. The rewrite is commoditized.
4. **Spec diffing and SDK generation are consolidating into the platforms.** Optic (YC S18) was acquired by Atlassian [background], and oasdiff is OSS. Postman bought Fern (Jan 2026), and Fern ships `fern diff` for breaking changes. Anthropic acquired Stainless (May 2026) and is winding down its hosted generator ([Speakeasy comparison](https://www.speakeasy.com/blog/comparison-sdk-generators-openapi); [Scalar](https://scalar.com/resources/stainless-wind-down)). The provider-side tooling layer is being absorbed by Anthropic and Postman.
5. **Unified APIs absorb breakage for a fee.** Merge, Nango and Paragon [background] make "the vendor changed the API" their problem. superglue (YC) now claims that when a vendor changes an API it "detects the break, proposes a fix, and applies it with one click" ([superglue](https://superglue.ai)).
6. **Dependabot/Renovate and Moderne, Grit, Codemod.com** handle SDK bumps and library codemods. Grit was absorbed by Honeycomb (R2-5). Dependabot adding "this bump has breaking API changes, here is a Copilot-generated fix" is a one-quarter feature for GitHub.

YC's own batches have **0 direct occupants** (yc_newest_rfs.md). That is consistent with "unclaimed", but equally consistent with "founders tried it and found no buyer".

## Attempts to disprove
- **Frequency per vendor is too low to justify a subscription.** A typical SaaS company depends on 5-15 APIs. Stripe never forces an upgrade, Meta forces one about every 2 years, and OpenAI model swaps are a one-line change. Doing this by hand costs a few engineer-days a year. That is a Claude Code prompt, not a vendor.
- **The rewrite is commodity and the detection is cheap.** Changelogs are public. An LLM can classify them, and $80/year page-diff tools already alert on them (PageCrawl). The only hard part is *verified* PRs, which need sandbox credentials and integration tests that most teams don't have for third-party calls. That is a security-review and setup burden, not a weekend MVP.
- **Trust objection.** For payments, practitioners explicitly refuse to outsource reliability ("involves money").
- **Providers own the relationship.** API vendors have the strongest incentive (retiring old versions is costly for them). They are shipping their own agent skills, and Postman and Anthropic now own the provider-side SDK toolchains.

## Sharpening tried
I narrowed it to **"version-deadline compliance for Shopify and Meta app developers"**: a GitHub App that reads the `X-Shopify-API-Version`/Graph version in use, tracks the quarterly sunset calendar, maps deprecated fields to call sites, and opens test-gated PRs before the delisting deadline. Pricing would be about $49-199 per app per month. This raises urgency (forced fall-forward, App Store delisting), names a buyer (Shopify Partner agencies and app studios), and gives a reachable channel (Shopify Partner community and app-dev Discords). It honestly improves E and slightly improves A. It also shrinks the market to small, price-sensitive buyers, and Shopify's own tooling plus generic agents remain a ceiling. I score the sharpened version. Unsharpened (generic VP Eng, all vendors) would be about 35 (A 7, B 5, C 5, D 6, E 4, F 8).

## Scores (sharpened)

**A. Proven demand / market: 7/20.** Breakage cadence is primary-sourced (37 OpenAI notices, Shopify quarterly with delisting, Meta about 2 years). But I found no money being spent on a standalone product, no competitor with revenue, and no quantified cost. The adjacent dollars go to unified APIs and the provider toolchain acquisitions (Fern, Stainless). Many free clones have zero pull.

**B. Sellable: 6/20.** No budget line. The fix is a prompt to an agent the team already pays for. Stripe makes upgrading optional. Payment and finance integrations face a trust objection. Price points are small ($49-199 per app). The provider-paid model is real but contested by the providers themselves (Stripe skills, Shopify dashboards).

**C. AI-durability: 5/20.** The value is the LLM doing changelog reading and code edits, which is exactly what improves in Claude Code, Codex and Copilot every quarter. GitHub can add API-change awareness to Dependabot cheaply. The only moat candidate is a curated, verified cross-vendor change feed plus runtime evidence of which endpoints are called. That is thin, and providers publish the feed for free.

**D. Evidence-backed real problem: 6/15.** Deprecation facts are solid, and the X/Twitter v1.1 and Shopify delisting cases are real. The cost evidence is one RFS anecdote (AWS 30%), a Postman time-on-APIs figure that doesn't isolate breakage, and a 5-comment Ask HN. Community complaints are scarce.

**E. Specific, reachable buyer: 6/10.** The sharpened buyer (Shopify and Meta app studios and agencies) is named and reachable through partner communities. The original "VP Eng" buyer is vague.

**F. Feasibility & wedge: 9/15.** A detection-plus-PR MVP takes weeks with public APIs. Test-verified PRs need sandbox credentials and test harnesses per vendor, which is real work. Demo-day differentiation against free OSS clones and "just ask Claude Code" is weak.

## Verdict
Breaking changes are real and calendared, but the per-company frequency is low, the code edit is already commoditized by general agents, and the API providers (Stripe skills, Shopify dashboards, Postman/Fern, Anthropic/Stainless) are moving into the space themselves. The RFS slot is "unclaimed" mostly because nobody has found a payer. Several free clones launched in 2026 with essentially zero traction. It scores well below ContextOps (58).

FINAL SCORE: 39/100

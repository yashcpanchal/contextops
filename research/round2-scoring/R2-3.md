# R2-3 scoring: AI-agent-aware change evidence (SOC 2 / PCI DSS 4.0 / SOX ITGC)

Evaluator: independent Opus, 2026-10-13. Inputs: TOP10_R2.md, RUBRIC.md, regulated.md, specs.md, plus new research (about 20 web and HN calls). Method note: the shared WebSearch budget ran out after 3 searches, so the rest of the research used direct WebFetch on known pages and the HN helper. The Reddit archive returned 429 twice and was skipped. Job-board pages returned 403, so **no job-posting evidence was gathered**. That is a gap, not a finding.

## The idea as scored
A GitHub App that builds, for each change, the chain requirement → ticket → agent session → PR → independent human review → tests → deploy. It flags segregation-of-duties (SoD) exceptions specific to agents, such as an operator who prompted the agent and then approved its PR, or an AI approval counted as review. It exports SOC 2 CC8.1, SOX ITGC and PCI 6.x evidence packs. The entry point is a free scanner.

## New evidence (what changed my view)

**For the idea**
1. **GitHub just created a new SoD hole.** On 2026-09-01 GitHub put into public preview a setting that lets Copilot submit formal PR approvals. That approval *can satisfy a repository's required-approvals rule* and can be scoped by file path ([aiunderstanding.org summary of the GitHub changelog](https://aiunderstanding.org/news/github-lets-copilot-submit-pull-request-approvals-in-public-preview)). An AI writing code and an AI approving it, inside a CC8.1 or PCI 6.2.3 scope, is exactly what an auditor sampling changes would treat as an exception. This is the best "why now" I found, and the regulated.md scout did not have it.
2. **Real companies are rebuilding change management around AI, with their auditors involved.** Mirage Security's founders describe letting Claude Opus approve "low-risk" PRs, sorting PRs by sensitive paths, requiring a human non-author approver for high-risk PRs, and running a weekly human retrospective over 100% of `ai-approved` merges. They say they worked through the approach with their auditor, Richey May ([Mirage eng blog](https://eng.miragesecurity.ai/posts/10x-change-management/)). This is a buyer in its own words, showing the pain is real and auditors are engaged.
3. **The category is drawing investment.** Kosli (Deutsche Bank CVC-led $10M Series A) now calls itself "governance infrastructure for AI SDLC". It names Deutsche Bank, ADCB, Norsk Tipping and an unnamed top-5 North American insurer as customers, publishes "Building a Control Framework for the AI SDLC", and runs an experiment governing AI code with Entire ([kosli.com](https://www.kosli.com/), [Kosli blog](https://www.kosli.com/blog/)). Entire announced a **$60M seed** on 2026-02-10 to store agent sessions as checkpoints alongside commits ([entire.io/blog](https://entire.io/blog)).
4. **A vendor survey.** A survey run by Token Security with the Cloud Security Alliance found that more than two-thirds of organizations cannot clearly separate agent actions from human actions. The same piece argues that CC8.1 SoD is "hollowing out" ([BleepingComputer, sponsored by Token Security, 2026-09-25](https://www.bleepingcomputer.com/news/security/with-the-rise-of-ai-agents-soc-2-should-adapt-or-risk-irrelevance/amp/)). This is vendor-sponsored, so weight it accordingly.

**Against the idea (attempted disproof)**
1. **Platform absorption of the core check has already started.** For Copilot's coding agent, GitHub already enforces that the person who assigned the issue to Copilot *cannot count* as the required approver, and that approval of the most recent push needs n+1 approvals ([GitHub Docs](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/cloud-agent/review-copilot-prs)). Since 2026-03-20, Copilot commits carry an `Agent-Logs-Url` trailer that links permanently to session logs "for auditing purposes" ([GitHub changelog](https://github.blog/changelog/2026-03-20-trace-any-copilot-coding-agent-commit-to-its-session-logs)). The idea's headline flag, "operator self-approves the agent's PR", is therefore native for GitHub's own agent. It is not native for locally run Claude Code or Cursor commits, which is where the gap remains.
2. **The provenance layer is funded and open source.** Entire ($60M), Git AI (2.8k stars; line-level attribution for Claude Code, Codex, Cursor, Copilot, Devin and others, plus a Teams product with PR, repo and team rollups and incident linkage) ([GitHub](https://github.com/git-ai-project/git-ai)) and GitHub's own trailers all cover the "agent session → commit" link. A student team would be building the compliance mapping on top of other companies' provenance data.
3. **An exact clone got zero pull.** "Show HN: EvidentTrail – Turn GitHub activity into continuous SOC2 audit evidence" detects AI commits through co-author trailers and bots, checks for human review before merge, maps to CC8.1 and ISO A.8.32, and exports SHA-256-manifested packs. It received **2 points, 0 comments, and "no users yet"** ([HN 47151920](https://news.ycombinator.com/item?id=47151920)). Other near-misses (Traceprompt, titanate "cryptographic receipts", Shadow VCS) also got about 0-2 points.
4. **Companies build it in-house.** Mirage built its whole AI-aware CC8.1 control with `dorny/paths-filter`, branch protection, CODEOWNERS and a scheduled workflow. In other words, a CTO did it with free GitHub Actions. That is the "won't build in-house" test failing for the SMB segment.
5. **GRC incumbents are moving next door.** Vanta advertises 25+ GitHub tests, including "Application changes reviewed", with no AI or bot language yet ([vanta.com](https://www.vanta.com/integrations/github)). Drata shipped AI Agent Visibility (inventory, owner, permissions, activity timeline, audit evidence) and AIUC-1 support. Neither yet covers coding-agent PRs ([Drata](https://drata.com/products/governance/agent-visibility)). Each is one feature release away.
6. **Still no primary-source regulator or auditor text.** The AICPA, PCAOB, PCI SSC and the Big 4 have published nothing on AI-authored changes that I could find. Every "auditors are asking" piece I read (Amit Kothari's guide, tianpan, Token Security, Scalr) is a practitioner or vendor assertion with no auditor quoted ([amitkoth.com](https://amitkoth.com/claude-code-soc2-compliance-auditor-guide/)). HN searches for "segregation of duties AI agent" and "SOC 2 Claude Code approval" return almost nothing.

## Sharpening (scored version)
I changed two things that the evidence supports:
- **Lead with "AI-in-the-control" exceptions, not attribution.** The flags would be: Copilot or bot approvals counting toward required approvals, operator-equals-approver on *non-GitHub* agents (Claude Code, Cursor and Codex local commits identified via Git AI notes, `Co-Authored-By` and Entire checkpoints), path-scoped AI approvals touching in-scope systems, and stale approvals. Provenance is consumed from Git AI, Entire and GitHub trailers, not rebuilt.
- **Make the auditor or vCISO the channel.** The output becomes a "100% population test" that small SOC 2 audit firms and fractional CISOs run across their clients. This answers the post-Delve demand for verifiable, non-templated evidence and turns one sale into many clients. Direct sales to fintech GRC leads, through the founder's Visa network, remain the second motion.

These changes raise E and B slightly. They do not fix the core problem that no one has yet been shown to budget for the AI-specific part.

## Scores

**A. Proven demand / market: 10/20.** Money for SOC 2 change evidence clearly exists: Vanta has more than $300M ARR, SOC 2 audits cost $20-60k, Kosli has a bank-led round, and Entire raised $60M for agent provenance. The AI-specific slice has no quantified spend. Its only clone has no users, and the one engaged buyer (Mirage) spent $0 on tooling. The trend is clearly upward because GitHub's AI-approval feature makes the problem real. Category money, not wedge money.

**B. Sellable: 9/20.** A budget line exists (GRC, audit prep). But the SMB version is a weekend of GitHub Actions (Mirage), GitHub enforces the basic Copilot SoD rule natively, and Vanta and Drata will add a "bot/AI approval" test as a checkbox inside a contract the buyer already pays for. Cross-agent neutrality (Claude, Cursor and Copilot together) and the auditor channel are real but thin reasons to pay separately. Large banks buy Kosli. Pricing is not credible yet; I would guess $5-20k per year, which is unvalidated.

**C. AI-durability: 10/20.** The good part is that the checks are deterministic and the value is independent attestation, which better models do not erode. The bad part is that the moat is neither data nor integrations, because provenance comes from GitHub, Entire and Git AI. The incumbents most likely to ship it (GitHub, Vanta, Drata, Kosli) are already one adjacent feature away. This is "a feature GitHub or Vanta will ship" risk on a 2-4 quarter horizon, not a quarter.

**D. Evidence-backed problem: 6/15.** The independent signals are the Mirage practitioner post, GitHub's own decision to block initiator self-approval (which implicitly confirms the SoD concern), and a vendor-sponsored CSA survey. There is no auditor or regulator primary source, no community thread with traction, and the closest Show HN got 2 points. The problem is plausible and documented by vendors, but buyers have not voiced it.

**E. Specific, reachable buyer: 7/10.** Head of GRC or compliance, or Head of Platform, at a 50-1,000-person fintech or SaaS company with SOC 2 or PCI scope. The founder's Visa background gives warm access, and SOC 2 boutique auditors and vCISOs are a compact, reachable channel. The buyer and the user differ (GRC versus engineering), and compliance buyers distrust unaudited vendors, especially after Delve.

**F. Feasibility & wedge: 10/15.** A GitHub App MVP takes 3-5 weeks on public APIs plus Git AI notes, and the free scanner is a good founder-led hook. The ease is also the weakness: EvidentTrail already shipped nearly the same thing. Differentiation from it, from Kosli and from a future Vanta test is unclear. Selling "audit evidence" also carries trust friction, which a student team would need SOC 2 or self-hosting to defuse.

## Verdict
The scout's 61 was too generous. New research shows that GitHub natively blocks Copilot initiator self-approval and writes audit trailers, that the agent-provenance layer is funded (Entire $60M) and open source (Git AI), that Kosli has repositioned onto "AI SDLC governance" with bank customers, and that a near-identical tool (EvidentTrail) launched to silence. The best surviving angle is GitHub's 2026-09 Copilot-approvals feature, which creates genuine AI-approves-AI SoD exceptions that GRC tools do not yet test for. That angle is a sharp interview hook, but not yet a company. Before building, run about 8 interviews with SOC 2 auditors and vCISOs and ask whether they have written an exception, or changed their sampling, for AI-authored or AI-approved changes in 2026. If fewer than 3 say yes, drop the idea.

Sources not verifiable in this session: investor names for Entire; Kosli pricing (quote-only); job-posting counts (blocked).

FINAL SCORE: 52/100
